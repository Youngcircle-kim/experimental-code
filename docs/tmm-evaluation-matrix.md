# TMM 실험의 비교 방법과 데이터 및 지표

2026년 10월 4일에 정리한 평가 설계안이다. 본실험과 RTX 3060 예비 실험의
범위를 구분한다. 새 QA나 외부 방법의 로컬 재현을 완료했다는 기록은 아니다.

## 비교 방법

본 성능표는 다음 여섯 기준선과 제안 방법의 총 일곱 방법을 목표로 한다.

| 방법 | 비교 목적 | 예비 실험 우선순위 |
|---|---|---|
| Uniform | 질문을 사용하지 않는 전역 균등 선택 | 기존 결과 활용 |
| Global Top-k | 질문 관련성만으로 전역 선택 | 기존 결과 활용 |
| Temporal-bin Top-1 | 동일 시간 구간마다 질문 관련성이 가장 높은 프레임 선택 | 기존 결과 활용 |
| AKS | 관련성과 시간적 커버리지를 고려하는 선행 선택기 | 외부 방법 두 번째 |
| WFS-SB | 경계·구간별 배분·내부 MMR을 사용하는 가장 가까운 선행 방법 | 외부 방법 첫 번째 |
| QCA | 구간 기여도 기반 배분과 관련성·다양성을 결합하는 선행 방법 | 본실험 포함 목표 |
| Proposed | 예비 진단 후 고정할 최종 방법 | 현재 D와 구별해 버전 고정 |

공식 저장소는 [AKS](https://github.com/ncTimTang/AKS),
[WFS-SB](https://github.com/MAC-AutoML/WFS-SB),
[QCA](https://github.com/hktk07/QCA)이다. QCA는 이번 확인에서
[ECCV 2026 공식 프로그램](https://eccv.ecva.net/virtual/2026/poster/4927)도
확인했다. 코드가 공개됐다는 사실과 현재 Windows 환경에서 재현 가능하다는
사실은 다르므로, 버전·가중치·의존성·출력 일치 확인 후 실행 조건을 동결한다.

원래 D, C, B, D Top-k와 새 모듈 제거 조건은 자체 구성요소 분석에 둔다.
C는 D와 구간 수를 맞춘 균등 경계 대조군이다. 원래 D를 새 방법인 것처럼
이름만 바꾸지 않으며, 기존 D와 새 방법의 직접 차이도 반드시 보고한다.

Video-Seer와 VideoTree는 QA 입력 구성과 부가 추론이 다른 전체 시스템이므로
같은 표에서 숫자만 비교하지 않는다. 관련 연구에서 다루고, 같은 QA 모델로
선택 모듈을 분리할 수 있는지 또는 비용을 포함한 시스템 비교가 가능한지
별도로 판단한다.

## 데이터와 평가 역할

| 데이터 | 본실험에서의 역할 | 사용할 범위 |
|---|---|---|
| Video-MME | 기존 결과와 연결되는 긴 영상 QA 검증 | 전체 900영상·2,700문항의 기술적 벤치마크 결과와 사용 이력을 감사한 새 영상 결과를 분리; long을 핵심 분석으로 지정 |
| LongVideoBench | 다른 데이터 분포에서 일반화 확인 | 공개 validation 1,337문항을 알고리즘 고정 후 평가; 전체와 공식 길이 구간별 정확도 |
| NExT-GQA | 근거를 실제 선택했는지 보조 진단 | validation의 사전 지정 표본으로 도구 확인 후 고정된 test 평가; 긴 영상 결과를 대체하지 않음 |
| 자체 근거 주석 | 사용자의 내부 선택 실패 가설 검증 | 기존 long dev에서 결과와 무관하게 선정한 24문항으로 시작; 논문의 독립 평가와 구분 |

[Video-MME 공식 자료](https://github.com/MME-Benchmarks/Video-MME),
[LongVideoBench 데이터 카드](https://huggingface.co/datasets/longvideobench/LongVideoBench),
[NExT-GQA 공식 자료](https://github.com/doc-doc/NExT-GQA)

Video-MME는 이미 결과를 본 99영상·297문항을 사용 이력에 표시한다. 전체 점수에
그 영상을 포함할 경우 완전히 독립적인 시험 점수라고 부르지 않는다. 새 long
평가 명단은 결과를 보기 전에 고정하고 다른 데이터와 영상 ID 중복을 검사한다.

LongVideoBench의 validation을 사용해 새 방법을 반복 조정하면 그 부분은 더
이상 일반화 검증 자료가 아니다. 필요하면 사전 분할한 영상 단위 개발 부분과
평가 부분을 구분한다. 공식 test는 정답 비공개이며 접근·평가 가능 여부를
확인하기 전에는 완료 가능한 평가로 약속하지 않는다.

주 비교는 영상 프레임의 효과를 보기 위한 자막·음성 없는 조건이다.
LongVideoBench의 기본 loader는 프레임과 자막을 교차 입력하므로, 자막을
제거한 결과에는 **without subtitles**를 명시한다. 자막을 사용한 기존 논문
점수와 직접 비교하지 않고 기준선도 모두 같은 입력 조건에서 실행한다.
자막을 추가하는 보조 실험은 별도 표로 두며 영상 선택과 텍스트 변화의 영향을
구분한다. [공식 LongVideoBench loader](https://github.com/longvideobench/LongVideoBench)

MLVU는 본실험의 추가 일반화가 필요하고 자원이 허용될 때 검토한다. 우선
두 긴 영상 QA 데이터와 별도 근거 평가의 완성도를 확보한다. 데이터셋 개수는
TMM 공식 필수 요건으로 제시하지 않는다.

## 주요 성능 지표

**주 성능 지표는 문항 단위 MCQ Accuracy**다. 방법과 예산별 정확도 및
사전에 지정한 기준선과의 차이를 %p로 보고한다. 최근접 기준선 WFS-SB와의
차이를 핵심 비교로, Uniform과의 차이를 기본 비교로 둔다. 확증 분석의
비교군과 다중비교 처리 방식은 본실험 전 동결한다.

본 성능표에서는 각 벤치마크의 공식 프롬프트·정답 파싱·채점 조건을 확인해
일관되게 적용한다. 응답 파싱 실패를 성공한 문항만 남기는 방식으로 제거하지
않고 공식 처리 규칙 및 실패율을 보고한다. 기존 6개 선택지 순서의
full-option likelihood 평균은 별도 통제 실험과 순서 민감도 지표다.
이 지표를 공식 원래 순서의 생성 답변 정확도와 섞지 않는다.

paired 차이의 95% 신뢰구간은 같은 영상의 문항을 묶은 bootstrap으로 구한다.
예비 실험은 기존 5,000회 설정을 유지한다. 개선·하락·동일 문항 수를 함께
보고하고, 선택지 순서 여섯 개를 독립 문항 여섯 개로 세지 않는다. 전체,
영상 길이, 질문 유형 분석을 구분한다.

## 근거 보존 지표

다음은 희소 프레임 선택을 위한 명시적인 진단 지표다. 공식 grounding 지표를
임의로 바꾼 것처럼 표시하지 않는다. B는 선택 프레임 수다.

| 지표 | 정의 | 해석의 한계 |
|---|---|---|
| Interval Hit@B | 선택 시각 중 하나 이상이 주석 근거 구간들의 합집합에 포함된 문항 비율 | 시간 구간에 들어갔다는 뜻이며 충분한 시각 증거 확보를 보장하지 않음 |
| In-interval Frame Fraction@B | 선택 B장 중 주석 구간 안에 들어간 프레임 비율의 문항 평균 | 간단한 집중도 진단; 높은 값만으로 필요한 상태의 다양성을 보장하지 않음 |
| Required Evidence Coverage@B | 사람 주석으로 정의한 필수 근거 그룹 중 충족한 그룹의 비율 | AND/OR 및 판독 가능성·시간 순서를 명시한 자체 주석에서만 사용 |
| Complete Evidence Rate@B | 적어도 하나의 충분 근거 대안 집합을 완전히 충족한 문항 비율 | 주석으로 확인한 근거에 대한 지표이며 인과적 사용 여부를 입증하지 않음 |
| QA and Complete Evidence | QA가 맞고 알려진 충분 근거도 포함된 문항 비율 | 자체 결합 지표이며 공식 Acc@GQA와 다름 |

근거 구간이 여러 개라고 모두 필수라고 가정하지 않는다. 대체 가능한 근거는
OR, 함께 필요한 상태는 AND로 표시한다. 판독 불가·음성 의존·근거 불완전은
unknown 또는 해당 원인으로 기록하고 지표별 분모와 제외 수를 공개한다.
선택 결과나 QA 정답률을 보고 근거 구간을 유리하게 수정하지 않는다.

내부 선택의 개선 여지는 **같은 구간별 quota로 알려진 충분 근거를 구성할 수
있는 문항 중 실제 선택이 그 근거를 놓친 비율**로 본다. 전체 후보에서의
가능성, quota 아래 가능성, 실제 선택 성공률을 별도로 보고한다. quota가
허용하지 않는 두 필수 상태를 내부 선택 실패로 분류하지 않는다.

NExT-GQA의 공식 지표에는 mIoP, IoP@0.5, mIoU 및 QA 정답과 IoP≥0.5를
함께 요구하는 Acc@GQA가 있다. 이들은 예측 **시간 구간**을 대상으로 한다.
우리 방법이 시간 구간을 출력하고 공식 평가 절차를 구현한 경우에만 해당
지표를 보고한다. 선택 프레임의 처음부터 끝까지를 임의로 연결해 공식
grounding 결과라고 하지 않는다.
[NExT-GQA 지표 정의](https://arxiv.org/html/2309.01327v2)

## 비용과 공정성

| 항목 | 보고 방식 |
|---|---|
| QA latency | 문항당 실제 QA 시간 중앙값과 분포; 순서 반복 수·채점 방식 명시 |
| 전처리와 선택 | decode, 특징 추출, 질문별 scoring, selection을 분리 |
| End-to-end latency | 최초 실행과 특징 캐시 재사용 실행을 구분; 여러 질문 간 비용 상각 방식 명시 |
| 메모리 | 최대 GPU 할당 메모리와 측정 범위; allocator reserved를 물리 VRAM으로 해석하지 않음 |
| 입력 예산 | 고유 프레임 수와 processor의 실제 시각 토큰 수 |
| 효율 곡선 | 16·32장 정확도와 총 시간·시각 토큰 사이의 관계; 64장은 선택적 확장 |

동일 QA 모델 안에서 해상도·정밀도·프롬프트·최종 프레임 수·정렬·채점을
맞춘다. 다른 backbone 간 시각 토큰을 같다고 가정하지 않는다. 특징 추출기는
각 방법의 원래 것을 쓰는 재현과 공통 추출기로 맞춘 선택 규칙 비교를 나눈다.
원래 scorer·FPS를 변경한 결과에는 변경 사항을 명시한다.

공통 후보 풀 비교에서는 최소 최대 예산만큼 고유 후보를 확보한다. 예를 들어
8초 영상의 2FPS 후보 16장으로 중복 없는 32장을 만들 수는 없다. 짧은 영상의
후보 FPS 보정 또는 충분한 native frame 사용 규칙을 사전에 고정하고 모든
방법·예산에 동일한 후보 풀을 적용한다. 후보가 모자랄 때 이미지를 복제해
32장이라고 보고하지 않는다.

## 11월 초까지의 실행 범위

RTX 3060 예비 실험에서는 기존 long dev 20영상·60문항, 현재 Qwen3.5-4B,
320×320, 16·32장 설정을 유지한다. 기존 Uniform·Global Top-k·Temporal-bin·
D·C 결과를 엄격한 입력 검증 후 활용한다. 외부 기준선은 WFS-SB부터
연결하고 다음으로 AKS를 확인한다. QCA는 본실험 목록에 포함하되 예비 단계에서
세 외부 방법의 전체 QA를 한꺼번에 시작하지 않는다.

근거 audit는 24문항으로 시작한다. LongVideoBench 전체와 NExT-GQA test는
방법을 고정한 후의 평가 자료로 남긴다. 본실험에서는 다른 계열 QA 모델을
추가하되 현재 GPU에서 실행 가능하다고 미리 가정하지 않는다.

이 구성은 [연구계획서](tmm-research-plan.md)를 구체화한 제안이다. 외부 코드의
설치·이식·재현, 새 데이터 다운로드, 근거 주석 및 추가 QA는 아직 실행하지 않았다.
