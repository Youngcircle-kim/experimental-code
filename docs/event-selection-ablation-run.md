# 320 조건의 구간 내부 선택 및 구간화·배분 기여 실험

이번 실험은 긴 dev 영상 **20개·60문항**, QA 입력 **320×320·16장**,
D2 최대 **128구간**을 유지한다. 먼저 **D의 구간 내부 균등 선택을 질문
관련성 Top-k로 바꾸면 정확도가 달라지는지** 확인한다. 이어서 내부 Top-k를
고정했을 때 내용 변화 기반 구간화와 질문 기반 장수 배분이 각각 도움이
되는지 비교한다.

기존 네 조건의 320 QA 결과를 검증해 재사용하고, 세 조건만 추가한다.
**새 QA는 최대 1,080회**이며, 같은 입력을 공유하면 실제 실행 수는 줄어든다.

현재 입력 검증과 전체 선택 계획 준비가 완료됐다. 저장된 준비 보고서는
`stage=prepared_no_decode_no_QA`, 20영상·60문항, 새 CLIP 추출 0회를
기록한다. 이번 계획에서 공유 가능한 신규 입력은 없어
`planned_unique_new_QA_calls=1080`이다. **전체 QA는 아직 실행하지 않았다.**

## 왜 이렇게 나누어 비교하는가

기존 D는 두 단계에서 정보를 압축한다. 먼저 질문과 관련 있는 구간에
프레임 수를 배분하고, 그 안에서는 균등하게 프레임을 고른다. 질문과 관련된
구간을 잘 찾았더라도, 균등하게 고른 프레임이 답에 필요한 순간을 놓칠 수 있다.
따라서 첫 비교에서는 **구간 경계와 배분 장수를 그대로 두고 내부 선택만
바꾼다**. 여러 요소를 함께 바꿨을 때보다 결과가 무엇을 말하는지 명확하다.

그러나 내부 Top-k가 좋아지더라도 그 개선이 이벤트 구조의 기여를 증명하지는
않는다. 전체 영상에서 점수 높은 프레임을 고르는 것만으로 충분할 수 있고,
질문 기반 배분 없이 구간 길이에 비례해 장수를 나누어도 충분할 수 있다.
이를 구분하기 위해 구간화와 배분에 대한 두 가지 조건부 비교를 추가한다.

현재 설정에서 가장 직접적인 변경인 내부 선택을 주 비교로 둔다. 구간화·배분
비교는 그 변경안의 작동 원인을 설명하는 보조 비교다. Top-k의 최소 시간
간격은 **0초**로 고정해, 관련성 선택과 시간 간격 제약을 동시에 바꾸지 않는다.
이 실험에는 상위 8구간 집중 배분, 새 캡션, 다양성 보정, 온도 탐색을 추가하지
않는다.

## 일곱 조건

| 결과 이름 | 구간화 | 구간별 장수 배분 | 구간 내부 선택 | QA 출처 |
|---|---|---|---|---|
| `D` | 저장된 D2 내용 변화 구간 | 저장된 질문 관련성 배분 | 균등 | 기존 320 결과 |
| `D_topk` | D와 정확히 같음 | D와 정확히 같음 | 질문–프레임 CLIP Top-k | 신규 |
| `B_topk` | D와 정확히 같음 | 구간 후보 수에 비례 | 질문–프레임 CLIP Top-k | 신규 |
| `C_topk` | D와 같은 구간 수의 저장된 D0 균등 구간 | 저장된 C의 질문 관련성 배분 | 질문–프레임 CLIP Top-k | 신규 |
| `uniform` | 전체 후보 | 해당 없음 | 전체에서 균등 16장 | 기존 320 결과 |
| `frame_top` | 전체 후보 | 해당 없음 | 전역 질문–프레임 CLIP 상위 16장 | 기존 320 결과 |
| `temporal_bin` | 후보 수가 비슷한 16개 구간 | 구간마다 1장 | 구간별 최고 CLIP 점수 1장 | 기존 320 결과 |

여기서 이벤트는 CLIP 특징 변화에 따라 나눈 **내용 변화 구간**이다. 사람이
주석한 의미적 사건 경계와 같다는 뜻은 아니다.

`D_topk`의 k는 문항마다 **기존 D가 해당 구간에 배정했던 장수**다.
배분이 0이면 그 구간에서 선택하지 않고, 1이면 균등 대표 프레임 대신
질문–프레임 점수가 가장 높은 한 장을 고른다. 여러 장을 배정한 구간에서는
그 수만큼 높은 점수의 서로 다른 프레임을 선택한다.

`B_topk`는 구간의 후보 수를 가중치로 사용해 기존 용량 제한·정수 배분
절차로 총 16장을 나눈다. 모든 구간에 같은 수를 주는 방식이 아니다.
고정 FPS에서는 시간 길이에 비례하는 배분의 근사지만, 불규칙 타임스탬프에서는
두 개념이 다르다. **B_topk도 내부 Top-k에는 질문을 사용한다.** 따라서
D_topk−B_topk는 질문 자체를 완전히 제거하는 비교가 아니라, 질문을 장수
배분에도 사용하는 것이 도움이 되는지 확인하는 비교다.

`C_topk`는 `segment_cap128_long`에 저장된 C의 경계·배분을 사용한다.
C의 실제 구간 수 K는 같은 영상의 D와 같으며 최대 128이다. D0의 경계는
후보 인덱스를 균등하게 나눈 것이다. **C_topk의 K구간과 Temporal-bin의
16구간은 다르다.** C는 구간별 관련성으로 장수를 배분하지만 Temporal-bin은
각 구간에서 항상 한 장을 고른다.

모든 Top-k는 최소 시간 간격 0, 같은 점수면 더 이른 후보 우선이다.
선택한 프레임을 최종적으로 시간순으로 정렬하며, 모든 조건에서 서로 다른
16장을 사용한다. 구간 수가 16보다 많으면 일부 구간에 0장이 배정될 수 있다.

## 무엇을 검증하는 비교인가

| 역할 | 비교 | 고정되는 요소 | 달라지는 요소와 해석 |
|---|---|---|---|
| **주 비교** | **D_topk−D** | D2 경계·문항별 정수 배분 | 구간 내부 균등 선택 → 질문 Top-k |
| 구간화 기여 | D_topk−C_topk | 실제 구간 수·관련성 배분 규칙·내부 Top-k | D0 → D2 구간화 정책 |
| 배분 기여 | D_topk−B_topk | D2 경계·내부 Top-k | 후보 수 비례 → 질문 관련성 장수 배분 |
| 실용 비교 | D_topk−Uniform | QA 입력 예산·모델·채점 | D_topk 전체 선택 절차의 효과 |
| 추가 비교 | D_topk−Global Top-k | 질문–프레임 점수·최종 예산 | 구간 구조와 배분을 유지하는 효과 |
| 추가 비교 | D_topk−Temporal-bin | 질문–프레임 점수·최종 예산 | 적응적 구간화·배분의 결합 효과 |

D_topk−C_topk에서 같은 것은 **배분 규칙**이다. 경계가 달라지면 구간 길이,
평균 특징, 질문 관련성 점수와 실제 정수 배분이 함께 달라질 수 있다.
따라서 이 차이를 경계 위치 정확도만의 효과라고 해석하지 않는다.

이번 구성에는 D0+후보 수 비례+내부 Top-k에 해당하는 `A_topk`가 없다.
또한 현재 320 조건의 B 내부 균등 선택을 신규 평가하지 않는다. 따라서
**조건부 기여를 확인하는 실험이며, 구간화×배분 또는 배분×내부 선택의 완전한
2×2 상호작용을 입증하는 실험이 아니다.** 효과를 단순히 더해 전체 개선을
각 요소의 독립적 기여로 나눌 수는 없다.

## 이전 실험과 다른 점

| 이전 실험 | 당시 질문 | 이번 실험에서 추가하는 확인 |
|---|---|---|
| D와 Uniform·Global Top-k·Temporal-bin의 320 비교 | D 전체가 단순 선택 규칙보다 좋은가 | 현재 D의 내부 선택과 구성요소 기여를 분리 |
| 기존 이벤트 내부 Top-k·상위 8구간 집중 실험 | 원래 설정에서 내부 선택·집중 배분이 도움이 되는가 | 현재 cap128·320·긴 dev 20영상 조건에서 재평가 |
| A/B/C/D factorial 및 cap128 C/D 실험 | 구간화·배분이 내부 균등 선택에서 도움이 되는가 | 내부 Top-k를 고정한 상태에서도 도움이 되는가 |
| 기존 보류셋 평가 | 당시 고정한 D가 새 영상에 일반화되는가 | 이번 변경안의 원인 탐색이며 새 독립 확증은 아님 |

기존 내부 Top-k 실험의 QA 결과를 현재 해상도·구간 수 조건에 그대로 합치지
않는다. 이번 신규 세 조건은 현재 320 입력으로 QA를 실행한다. 재사용하는
것은 검증된 **동일 320 조건의 기존 네 비교군 결과**와 선택에 필요한
저장 경계·배분·CLIP 점수다. C의 과거 QA 정확도를 C_topk 결과로 복사하지
않는다.

이번 구성은 저장된 자료로 할 수 있는 추가 실험이며 알고리즘의 선행연구 대비
신규성을 입증하지 않는다. Global Top-k와 Temporal-bin 역시 이 저장소의
명시된 선택 규칙으로, 외부 논문 전체를 재현한 결과가 아니다.

## 입력 고정과 재사용 검증

- 기본 입력은 `outputs/selector_compare320_long`이며, 기존 네 조건의
  완료된 320 결과와 연결된 소스 프로토콜을 검증한다.
- C/D 경계·배분은 연결된 `outputs/segment_cap128_long`에서 가져온다.
  후보 풀·문항 집합·설정·소스 해시가 현재 비교와 일치해야 한다.
- 후보와 CLIP은 기존 **224×224 선택 조건**을 유지한다. 문항별로 저장된
  질문–프레임 점수를 사용하므로 **새 CLIP 추출은 0회**다.
- 선택 계획 준비는 모델 로딩·영상 디코딩·QA 없이 저장된 자료에서 수행한다.
  실제 평가 때 원본을 디코딩하고 선택된 프레임을 **320×320**으로 추출한다.
- QA 모델·가중치 revision·BF16·SDPA·프롬프트·선택지 로그우도 채점 및
  길이 정규화·문항별 선택지 순서 6개를 유지한다.
- 선택기는 영상의 저장된 특징·점수와 질문만 사용한다. 선택지·정답·캡션·
  사람이 찾은 근거를 선택 규칙에 넣지 않는다.
- 같은 문항에서 실제 선택 입력·해상도·모델·프롬프트·선택지 순서가 같은
  실행만 공유한다. 서로 다른 문항의 결과를 프레임이 같다는 이유로 공유하지
  않는다.
- 소스·코드·설정·대상 범위가 달라지면 기존 출력 폴더에서 재개하지 않는다.

## 실행 명령

PowerShell:

```powershell
Set-Location C:\Users\dudgh\experimental-code
```

읽기 전용 입력 검사:

```powershell
.\.venv\Scripts\python.exe -B -m event_caption_pilot.event_selection_ablation_dev --check-inputs
```

이 명령은 원본 결과의 출처와 저장된 선택 자료를 확인한다. GPU 추론이나
영상 디코딩을 수행하지 않는다. 영상 픽셀과 실제 QA 런타임 검증은 evaluate
단계에서 추가로 수행한다.

선택 계획 고정:

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.event_selection_ablation_dev --phase prepare --output-dir outputs/event_selection320_long
```

기본 phase도 `prepare`다. 이 단계는 모델·영상 디코딩·QA 없이 준비만 하고
끝난다. 계획과 코드가 확정되면 같은 폴더에서 QA를 실행한다.

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.event_selection_ablation_dev --phase evaluate --output-dir outputs/event_selection320_long
```

신규 세 조건의 최대 실행량은 **60문항 × 3조건 × 6순서 = 1,080회 QA**다.
QA 한 번은 한 선택지 순서에서 모든 선택지의 점수를 계산하는 단위이며,
모델 forward 한 번과 같지 않다. 기존 네 조건은 새로 추론하지 않는다.
중단되면 **위 evaluate 명령을 그대로 다시 실행**한다. 완료된 순서의
체크포인트를 검증하고 재사용한다. 같은 폴더에 동시에 두 실행을 시작하지
않는다.

한 영상·한 문항의 smoke는 별도 출력 폴더를 사용한다. prepare와 evaluate에
같은 대상 옵션을 전달한다.

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.event_selection_ablation_dev --phase prepare --max-videos 1 --max-questions 1 --output-dir outputs/event_selection320_smoke
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.event_selection_ablation_dev --phase evaluate --max-videos 1 --max-questions 1 --output-dir outputs/event_selection320_smoke
```

smoke의 신규 QA 상한은 18회다. smoke 결과를 60문항 전체 성능으로
보고하지 않는다. 전체 실행은 대상 축소 옵션 없이 위 전체 폴더에서 수행한다.

완료된 결과만 다시 집계하려면:

```powershell
.\.venv\Scripts\python.exe -B -m event_caption_pilot.event_selection_ablation_dev --phase summarize --output-dir outputs/event_selection320_long
```

기본 `--source-dir`은 `outputs/selector_compare320_long`이다. 다른 소스를
사용할 때는 입력 검증이 통과해야 하며, 같은 실험이라고 임의 간주하지 않는다.

## 결과와 해석

전체 QA가 완료된 뒤 전달할 파일:

```text
C:\Users\dudgh\experimental-code\outputs\event_selection320_long\handoff.json
```

`handoff.json`은 전체 대상의 모든 조건이 완료된 뒤 생성한다. 준비 단계의
선택 계획이나 중간 진행 파일을 최종 정확도 결과로 대신하지 않는다.
각 조건의 정확도, 사전 지정한 차이와 95% 신뢰구간, 개선·하락·동일 문항 수,
QA 비용을 함께 확인한다. 문항별 선택 인덱스와 시간, 구간·배분 계획 및
원시 QA 결과도 같은 실행 폴더에 보존한다.

| 파일 | 내용 |
|---|---|
| `prepare_complete.json` | 준비 상태, 대상 수, 신규 QA 계획 수, 새 CLIP 추출 수 |
| `protocol.json` | 소스·코드·설정 해시, 조건·주 비교 정의 |
| `selection_plans.json` | 문항별 고정 선택 인덱스, 신규 조건의 경계·배분·선택 진단 |
| `trials/`, `questions/` | 순서별 QA 및 완료 문항 체크포인트 |
| `decode/` | 실제 영상 디코딩 검증 기록 |
| `progress.json` | 평가 진행 상태와 완료 문항 수 |
| `results.json` | 일곱 조건의 문항별 원시 결과와 전체 요약 |
| `question_metrics.csv` | 문항별 6순서 평균 정확도와 조건 간 차이 |
| `selected_frames.csv` | 문항·조건별 실제 선택 인덱스와 타임스탬프 |
| `handoff.json` | 완료된 비교의 최종 전달 요약 |

최종 JSON에서 주 비교 키는 `D_topk_minus_D`다. 기여 비교는
`D_topk_minus_C_topk`, `D_topk_minus_B_topk`, 실용 비교는
`D_topk_minus_uniform`이다. `D_topk_minus_frame_top`과
`D_topk_minus_temporal_bin`도 제공하며, 기존 주 비교 `D_minus_uniform`을
참고값으로 함께 보존한다. 정확도와 차이의 평균·신뢰구간은
`overall.metrics`, 개선·하락·동일 문항 수는 `paired_question_changes`에 있다.

문항별 6개 선택지 순서의 정답 여부를 먼저 평균하고, 모든 문항에 동일한
가중치를 준다. 같은 영상의 문항을 묶어 조건 간 짝을 유지하는 **영상 단위
paired bootstrap 5,000회**로 정확도와 차이의 95% 신뢰구간을 구한다.
순서 반복 6개를 독립 문항으로 세지 않는다. 개선·하락·동일은 문항별
순서 평균을 비교한 개수다. 영상 하나의 smoke에는 영상 간 불확실성을
추정할 표본이 없으므로 이 신뢰구간을 제공하지 않는다.

주 비교는 D_topk−D다. 구간 하한이 0보다 크면 현재 dev에서 내부 Top-k의
개선을 뒷받침한다. 0을 포함하면 개선이 없다고 단정하지 않고, 이 표본으로
방향을 확정하기 어렵다고 보고한다. 나머지 비교의 신뢰구간은 다중비교
보정 전 개별 구간이며, 유리한 비교만 골라 주 결과로 바꾸지 않는다.

해석할 때 다음을 구분한다.

- D_topk−D가 양수면 현재 D의 경계·배분을 유지한 내부 선택 변경의 이득이다.
- D_topk−B_topk가 양수면 D2와 내부 Top-k를 유지할 때 질문 기반 장수 배분의
  추가 이득이다. 내부 Top-k까지 없앨 때의 배분 효과를 말하지 않는다.
- D_topk−C_topk가 양수면 내부 Top-k와 관련성 배분 규칙 아래 D2 구간화
  정책의 이득이다. 사람의 사건 경계가 더 정확히 검출됐다는 증거는 아니다.
- D_topk가 D보다 좋아도 Uniform이나 Global Top-k보다 좋다고 자동으로
  결론 내리지 않는다. 각각의 직접 비교와 신뢰구간을 확인한다.
- 선택된 CLIP 점수가 높아졌다는 사실은 QA에 필요한 근거를 더 잘 찾았다는
  증명과 다르다. 근거 주석 없이 evidence recall을 보고하지 않는다.

이번 대상은 이미 설계·튜닝에 사용한 dev이며, 보류 결과까지 확인한 뒤 만든
후속 탐색이다. 따라서 이번 결과를 독립 확증으로 부르지 않는다. 이후
변경안을 고정해 일반화 성능을 확인하려면 **이번 설계와 선택에 사용하지 않은
새 영상 표본**이 필요하다. 이미 관측한 holdout을 재사용하면 그 상태를
명시하고 새로운 독립 검증으로 주장하지 않는다.

## 비용 지표의 범위

보고하는 시간·최대 GPU 메모리·시각 토큰은 **QA 비용**이다. 선택용 CLIP
특징·점수·구간화를 재사용하므로 이번 실행의 새 CLIP 추출은 없지만,
전체 방법의 특징 추출·선택 비용이 0이라는 뜻은 아니다. 재사용한 전처리와
선택 비용을 QA 비용에 합산하지 않는다.

기존 네 조건의 시간은 과거 실행 측정값이고 신규 세 조건은 이번 실행값이다.
신규 조건이 기존 입력과 같아 과거 QA를 공유하면 그 시간도 과거 측정이다.
따라서 실행 출처를 구분해 보고하며, 이 비교만으로 전체 처리 속도나 자원
효율의 우위를 주장하지 않는다. Uniform은 CLIP 없이도 실행할 수 있으므로
전체 비용 비교에는 별도 측정이 필요하다.

`resources`의 조건별 `qa_seconds_median`은 **선택지 순서 한 번의 QA 시간**
중앙값이다. `visual_tokens_per_QA_call`은 1,600이며,
`option_order_repeats_per_question`은 6이다. 1,600을 여섯 순서 전체의
합계 토큰 수로 읽지 않는다. `qa_origins`는 과거 소스의 `source`와 이번
실험의 `this_experiment`를 구분한다. `selection_and_feature_seconds`는
측정하지 않았으므로 `null`이다.

`unique_new_QA_calls`와 `unique_new_QA_seconds`는 이번 실험에서 고유한
신규 QA의 총 호출 수와 시간 합계다. 조건 사이에서 공유한 같은 실행은 한 번만
세고, 과거 소스에서 가져온 QA는 제외한다. 재개한 경우에도 완료된 이번
실험 전체를 기준으로 집계한다. `progress.json`의
`new_QA_calls_this_invocation`은 현재 명령 실행에서 추가한 호출 수이므로
두 값의 범위가 다르다.

## 구현 검증

신규 실행기 관련 **26개를 포함한 전체 테스트 217개**와 Ruff 검사를 통과했다.
의도한 요소만 변경하는지,
동점·간격 0 선택, 같은 입력 공유 시 조건별 계획 보존, 320 입력 검증,
기존 결과 보존, 중단된 순서부터 재개, 프로토콜·계획·체크포인트 변조 감지,
순서 반복을 문항 안에서 평균하는 집계를 확인했다. 이 검증은 전체 60문항의
신규 QA 정확도를 측정한 결과가 아니다.

실제 영상 `895`의 문항 `895-1`에서도 원본을 다시 디코딩했다. 후보
5,081장의 해시가 기존 자료와 일치했고, 일곱 조건 모두 시간순의 서로 다른
320×320 프레임 16장을 구성했다. 기존 네 조건은 저장된 QA 픽셀 해시와
정확히 일치했다. 이 추가 점검의 QA와 CLIP 호출은 모두 0회이며, 기록은
`tmp/event_selection320_pixel_smoke.json`에 있다.

## 체크포인트 비교 오류 수정 (2026-10-01)

실제 QA의 `option_scores`는 메모리에서 tuple이고 JSON에서는 list다.
두 표현을 직접 비교해 발생하던 `Question and trial checkpoints disagree`
오류를 수정했다. 새 결과는 JSON 표현으로 정규화해 저장·사용하고, 재검증도
같은 표현으로 비교한다. 점수 값이 달라진 체크포인트는 계속 거부한다.

이미 실행한 `event_selection320_long`은 원래 프로토콜과 QA 파일을 보존한다.
`checkpoint_compatibility.json`에 이번 수정 전후의 정확한 프로토콜·실행기
해시를 기록해 같은 evaluate 명령으로 재개한다. 이 기록은 다른 코드 변경,
입력·선택 계획·설정 변경에는 적용되지 않는다. 출력 폴더를 삭제하거나
프로토콜 해시를 수동 변경할 필요가 없다.

수정 후 전체 테스트 224개와 Ruff를 통과했다. 실제 저장된 첫 문항의
18개 QA도 점수·선택지 순서·320 입력·체크포인트를 재검증했다. 원래
프로토콜·계획·준비 보고서와 18개 QA 파일의 바이트 해시는 수정 전과 같고,
수정 검증 과정에서 새 QA나 CLIP 추론은 실행하지 않았다.
