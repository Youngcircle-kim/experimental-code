# 선택 프레임을 고정한 224 → 320 해상도 실험

기본 대상은 완료된 `outputs/segment_cap128_long`의 긴 영상 20개·60문항이다.
기존 C·D가 선택한 **16개 후보 인덱스, 타임스탬프, 질문, 선택지 순서 6개**를
그대로 사용한다. 이벤트 분할, CLIP 점수, 배분 및 프레임 선택은 다시 하지 않는다.
사람이 지정한 1035·1036 프레임이나 캡션은 추가하지 않는다.

QA 입력 이미지만 원본 영상에서 320×320으로 추출하고, Qwen의 이미지당 픽셀
상한을 50,176에서 102,400으로 바꾼다. 모델·가중치·BF16·SDPA·프롬프트·
선택지 전체 log-likelihood 채점은 유지한다. 정사각형 resize와 보간법도 기존
224 실험과 같다. 종횡비 정책을 바꾸는 실험은 포함하지 않는다.

## 전체 실행

PowerShell, 작업 경로 `C:\Users\dudgh\experimental-code`:

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.resolution_dev --side 320 --output-dir outputs/resolution320_cap128_long
```

준비 단계는 따로 필요 없다. 기존 224 QA 결과를 대조군으로 읽고, 320 QA만
최대 `60문항 × C/D 2조건 × 선택지 6순서 = 720회` 실행한다.
한 QA 호출은 선택지별 모델 forward를 포함하므로 forward 720회라는 뜻은 아니다.
같은 문항에서 C·D가 같은 16장을 선택했다면 동일 해상도 QA를 공유한다.

중단되면 **같은 명령을 다시 실행**한다. 선택지 순서별 체크포인트가 남으며,
완료된 문항은 영상 디코딩과 모델 추론을 모두 생략한다. 소스·코드·설정·대상
범위가 달라지면 같은 폴더의 재개를 거부한다. 기존 실험 폴더는 수정하지 않는다.

실행 전 입력만 검사하려면 위 명령에 `--check-inputs`를 붙인다.
모델을 로드하거나 출력 폴더를 만들지 않는다.

## 작은 실행과 현재 환경의 대조군 재현

첫 영상의 첫 질문을 사용하며, 정오답이나 사람의 근거 주석으로 고르지 않는다.
224를 현재 환경에서 다시 실행해 기존 결과의 재현 여부와 처리 비용을 함께 본다.

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.resolution_dev --conditions D --max-videos 1 --max-questions 1 --rerun-control --output-dir outputs/resolution320_smoke_v2
```

D 조건의 224·320을 합쳐 12 QA 호출이며, 정확도는 한 질문의 진단이다.
6개 선택지 순서를 독립된 6문항으로 해석하지 않는다.
`results.json`의 `control_reproduction`에 기존 224 예측 일치 여부와
선택지 점수 최대 절대 차이를 기록한다.

전체 실험도 224를 다시 실행하려면 전체 명령에 `--rerun-control`을 추가하고
새 출력 폴더를 사용한다. 새 QA 호출 상한은 1,440회로 늘어난다.

## 원본과 해상도 검증

- 영상을 한 번 순차 디코딩하면서 모든 224 후보 픽셀·타임스탬프의 해시를
  기존 실험과 비교한다. 일치하지 않으면 QA 전에 중단한다.
- 선택된 시점의 원본 RGB에서 직접 320 이미지를 만든다. 224 이미지를 확대하지 않는다.
- 후보 전체를 320 배열로 쌓지 않고, 필요한 선택 프레임만 메모리에 남긴다.
- 모델 처리 후 이미지 크기와 `image_grid_thw`를 검사한다. 320 입력이 다시
  224로 축소되면 중단한다. 현재 모델에서 16장의 시각 토큰은 784 → 1,600개다.
- QA 체크포인트에는 해상도, 실제 입력 픽셀 해시, 선택 인덱스, 질문, 선택지
  순서, 프로토콜 해시를 포함한다. 해상도가 다른 QA 결과를 재사용하지 않는다.
- 디코딩 기록에는 원본 크기와 320보다 작은 원본 프레임 수를 남긴다.

## 결과와 해석

전달할 파일은 **`outputs/resolution320_cap128_long/handoff.json`**이다.

- `D_320_minus_224`: D의 해상도 효과, 기본 주 비교.
- `C_320_minus_224`: C의 해상도 효과.
- `D_minus_C_224`, `D_minus_C_320`: 해상도별 C/D 차이.
- `change_in_D_minus_C`: 해상도를 올린 뒤 C/D 차이가 얼마나 변했는지.
- 각 조건의 정확도와 정답 선택지의 점수 우위(gold margin).

문항 안에서 선택지 순서별 정확도를 먼저 평균하고, 영상 단위 5,000회
bootstrap으로 CI를 계산한다. 한 영상만 사용한 진단에는 CI를 붙이지 않는다.
`question_metrics.csv`에는 문항별 값, `results.json`에는 원시 선택지 점수를 저장한다.

자원 지표는 QA 호출당 시간, 실제 입력 토큰 수, PyTorch 최대 allocated/reserved
메모리다. 메모리는 모델 파라미터를 포함하며 다른 프로그램·드라이버의 메모리는
제외한다. 기본 실행의 224 시간은 과거 측정이므로 엄밀한 현재 환경의 속도 비교는
`--rerun-control` 결과로 한다. 초기 모델 로딩과 영상 디코딩은 QA 시간에서 제외한다.

해상도 효과는 기존 선택 결과를 조건으로 한 QA 효과다. 근거 프레임을 놓치는
선택기의 한계를 해결하거나 전체 근거 재현율을 측정하는 실험은 아니다.

## 다른 저장된 선택 결과 사용

이벤트 점수 비교 실험의 세 조건을 그대로 고정해서 확인할 수도 있다.
기본 C/D 해상도 실험과는 별도 폴더에서 실행한다.

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.resolution_dev --source-dir outputs/event_score_cap128 --conditions pooled_mean frame_max frame_topn_mean --side 320 --output-dir outputs/resolution320_event_score
```

`--side 448` 등 다른 크기는 32의 배수로 지정하고 반드시 새 출력 폴더를 사용한다.
큰 해상도의 실행 가능 여부는 이번 320 진단만으로 보장하지 않는다.

## 실제 실행 확인 — 2026-09-28

`outputs/resolution320_smoke_v2`에서 첫 영상 895의 첫 질문 895-1, D가 고른
16장을 그대로 사용했다. 224·320 각각 선택지 순서 6개를 완료했고, 완료 결과의
`--summarize-only` 재개도 모델 로딩이나 디코딩 없이 성공했다.

| 측정 | 224×224 | 320×320 |
|---|---:|---:|
| 시각 토큰 | 784 | 1,600 |
| QA 한 번의 시간 중앙값 | 3.89초 | 6.71초 |
| PyTorch 최대 allocated GPU 메모리 | 9.223GiB | 9.697GiB |
| 이 질문의 정답 선택지 순서 수 | 1/6 | 0/6 |

기존 224 선택지 점수와 재실행 값의 최대 절대 차이는 0이었다.
320은 이 진단에서 메모리 부족 없이 실행됐지만 정확도 개선은 없었다.
선택지 순서 6개는 한 문항의 반복이며, 전체 성능 변화는 60문항 비교로 판단한다.
이 측정이 모든 질문이나 동시 실행 환경의 메모리 여유를 보장하지는 않는다.

검증: 원본 픽셀·시각 대응, 원본에서 직접 resize, 해상도별 캐시 분리,
실제 처리 해상도 확인, 중단 후 순서 단위 재개에 대한 테스트 5개 통과.
