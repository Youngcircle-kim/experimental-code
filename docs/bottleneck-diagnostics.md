## 확인 순서와 지표 해석

### 1. 질문에 따라 배분과 입력이 바뀌는가?

`videos.csv`의 `unique_allocations`, `unique_selections`를 본다.
1이면 해당 영상의 완료된 질문들이 같은 배분 또는 같은 선택을 사용했다는 뜻이다.
질문이 1개뿐인 영상은 질문 간 동일 배분 비율의 분모에서 제외한다.
A/B는 질문을 사용하지 않으므로 동일 배분이 예상된다.

C−A, D−B의 `same_selection_fraction`은 완전히 같은 후보 프레임 집합을
고른 문항 비율이다. `shared_frame_fraction`은 교집합 크기/프레임 예산이다.
정확히 같은 후보 인덱스만 센다. 인접 프레임이나 시각적으로 비슷한 프레임이
얼마나 겹치는지를 나타내지는 않는다.

### 2. 구간 수와 예산이 어떤 선택을 유도하는가?

`hit_max_segments`와 `events_exceed_budget`를 본다.
A/C의 구간 수는 D2에 맞추므로 A/C의 상한 도달도 같은 값이다.
`zero_event_fraction`은 0장을 받은 구간 비율이다.
`omitted_candidate_fraction`은 0장 구간에 속한 후보 수/전체 후보 수이다.
이는 모든 미선택 프레임 비율이 아니며, 정답 근거 누락률도 아니다.
후보 수는 일정 FPS에서 지속시간의 근사일 뿐 정확한 경계 시각은 아니다.

`max_frames_per_event=1`이면 선택된 모든 구간에서 중앙 부근 한 장만 사용한다.
`rank_only_regime=true`이면 softmax 가중치×예산이 모든 구간에서 1 미만이다.
이 경우 정수화 과정은 관련성 상위 구간에 한 장씩 주는 형태가 된다.
온도를 바꿔도 이 조건과 순위가 유지되면 배분이 같다.
**온도에 둔감한 것과 질문에 둔감한 것은 다른 현상이다.**

### 3. 온도를 바꿨을 때 입력이 달라지는가?

온도 재계산은 저장된 raw cosine, 구간, 후보 수, 프레임 예산을 고정하고
기존 `allocate_frames()`와 `sample_indices()`를 재사용한다.
`allocation_changed`는 원 실행 대비 배분 벡터 변화 여부이다.
선택 구간의 Jaccard는 교집합/합집합으로, 프레임 교집합 지표와 구분한다.
같은 구간도 1장→2장으로 바뀌면 중앙 한 장에서 양 끝 두 장으로 바뀌기 때문이다.

이 파일에는 **변경된 선택의 QA 정확도가 없다.** 후보 특징 전체가 없으므로
새 온도의 특징 중복도나 새 이벤트 경계도 계산하지 않는다. 온도나 구간 수의
최적값을 결정하는 실험으로 사용하지 않는다.

### 4. 근거 누락과 QA 실패를 구분하는 수동 검토

`review_queue.csv`에서 우선 `comparison=D_minus_C`의 개선/악화 문항,
그리고 `duration_group=long`, `comparison=D_minus_B`를 본다.
동일 점수이며 양쪽 모두 틀린 문항도 함께 검토한다. 목록은 차이의 절댓값
순서이므로 이를 대표 표본이나 전체 실패 비율로 해석하지 않는다.

각 evidence 열에는 `yes`, `no`, `unknown`을 기록한다. 정답 근거는 여러 장면이나
시간 순서가 필요할 수 있으므로 필요한 근거 전체가 포함됐는지 확인한다.

| 관찰 | `failure_category` 예시 |
|---|---|
| 원 영상에 근거가 있지만 후보 풀에서 확인되지 않음 | `candidate_missing` |
| 후보에는 근거가 있지만 필요한 구간에 0장을 배정 | `allocation_miss` |
| 필요한 구간에 배정했지만 균등 샘플링이 근거를 놓침 | `within_event_miss` |
| 충분한 근거를 입력했지만 해당 순서에서 오답 | `qa_or_scoring` |
| 현재 자료로 판별 불가 | `unknown` |

여러 원인이 가능하면 `notes`에 조건별로 기록한다. 이 스크립트는 근거 주석이나
영상 픽셀을 읽지 않으므로 위 범주를 자동으로 판정하지 않는다.
선택지 순서 평균 정확도의 개선은 단순한 오답→정답 전환과 다르다.
필요한 경우 원 `questions/*.json`의 순서별 `trials`를 같이 확인한다.

## 집계와 입력 검증

- 정확도는 문항 내부 순서 평균 후 문항에 같은 가중치를 준다.
- 구간 누락 비율은 문항별 비율의 평균, 영상 비율은 영상에 같은 가중치다.
- 기술통계이며 새 신뢰구간·유의성 검정·다중 비교 보정은 하지 않는다.
- 프로토콜/후보 해시 연결, 중복 문항, 순서 쌍, 계획/결과 일치,
  연속 구간·예산·정수 배분, 기존 배분 재현, 완료 문항 수를 확인한다.
- 원 영상의 픽셀 해시를 새로 계산하거나 원 실행 환경 전체를 검증하지는 않는다.
- 자동 생성 결과는 연구 가설을 좁히기 위한 진단이며 인과적 병목의 확정은 아니다.

충분했는지를 우선 확인할 수 있다. 온도 변화만으로 성능이 좋아질지는
이 진단으로 알 수 없다.
