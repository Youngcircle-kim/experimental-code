# 이벤트 분할 평가 데이터 선택

2026-09-15 기준 코드 및 공식 데이터 문서를 검토한 제안입니다.
아래 데이터셋의 다운로드·annotation 변환·경계 채점은 아직 이 저장소에 구현되지 않았습니다.

## 권장 순서

| 우선순위 | 데이터 | 이 실험에서 확인할 것 |
|---|---|---|
| 1 | Kinetics-GEBD | D0/D1/D2가 사람이 표시한 일반적인 이벤트 변화 경계를 찾는가 |
| 2 | TAPOS | 하나의 스포츠 행동 안에서 세부 행동이 바뀌는 순간도 찾는가 |
| 3 | Kinetics-GEB+ | 경계 전후 상태 변화가 생성한 설명문에 반영되는가 |

**하나만 시작한다면 Kinetics-GEBD를 사용합니다.** 분류 라벨만 있는 Kinetics-400과 구분해서 GEBD 경계 annotation을 함께 받아야 합니다. 클래스에 제한되지 않은 이벤트 경계 평가라는 목적이 현재 검출기에 가장 가깝습니다. 원본 자료에는 행동·상호작용 대상 변화와 촬영 전환 등의 유형 정보가 있으므로, 가능하면 유형별 결과도 별도로 확인합니다. [공식 저장소](https://github.com/StanLei52/GEBD)

TAPOS는 스포츠 활동의 세부 행동 경계를 제공합니다. 같은 장면에서 움직임만 바뀌는 상황을 추가로 검토하기에 좋습니다. 전체 원본 영상 시간과 action instance 내부 frame index를 혼동하면 안 됩니다. 같은 원본에서 잘라낸 instance를 dev/eval에 나눠 넣지 않아야 합니다. 현재 입력 검증은 원본당 하나의 Video만 허용하므로 여러 instance를 처리하려면 원본 단위 통합이나 별도 evaluator가 필요합니다. [공식 프로젝트 및 annotation 형식](https://sdolivia.github.io/TAPOS/)

GEB+는 경계에 연결된 상태 변화 설명문을 제공합니다. 공식 저장소에 필터링된 경계와 raw annotation, 프레임 다운로드 링크가 있습니다. 다만 **경계 전후 변화를 설명하는 caption**과 현재 코드의 **구간 내부 관측을 요약하는 caption**은 단위가 다릅니다. annotation을 그대로 구간 caption의 정답으로 놓고 채점하면 안 됩니다. Kinetics-GEBD와 원본 영상이 겹칠 수 있으므로 독립 평가로 셀 때도 원본 ID를 대조해야 합니다. [공식 저장소](https://github.com/Yuxuan-W/GEB-Plus)

현재 `prepare_data.py`의 Perception Test 3개 영상은 실제 QA 연결의 동작 확인용입니다. 이 준비 코드가 가져오는 annotation에는 이벤트 경계 정답이 없으므로 분할 정확도를 입증하는 용도로 적절하지 않습니다.

## 최소 평가 절차 제안

1. 초기 동작 확인은 GEBD 영상 약 100개로 시작합니다. 이 숫자는 작업량을 줄이기 위한 제안이며 공식 평가 규모가 아닙니다.
2. 임계값·window·최소 길이는 train에서 떼어 둔 원본 영상 단위 dev에서 결정합니다. 공식 validation은 고정한 설정으로 평가합니다.
3. D0/D1/D2와 D1/D2 각각에 구간 수를 맞춘 D0를 모두 평가합니다.
4. 경계 timestamp를 공식 evaluator 형식에 맞춰 내보내고 precision, recall, F1을 계산합니다. 공식 예시는 영상 길이의 5%를 시간 오차 허용치로 사용하며 여러 평가자의 정답 처리 규칙도 포함합니다. 임의로 모든 평가자의 경계를 합치지 않습니다. [공식 평가 코드](https://github.com/StanLei52/GEBD/blob/main/Challenge_eval_Code/eval.py)
5. 경계 수/분, 과분할·미분할 사례, 변화 유형별 실패 사례를 함께 봅니다.
6. 최종 후보 풀 2fps 외에 4fps·8fps 등 더 조밀한 진단을 비교합니다. 이는 권장 ablation이며 공식 프로토콜의 FPS라는 뜻은 아닙니다.

2fps 후보 풀의 시간 간격은 0.5초입니다. 10초 영상에서 5% 허용 오차 역시 0.5초이므로 관측 간격 자체가 평가에 큰 영향을 줍니다. `window_size`와 `min_segment_frames`는 초가 아닌 관측 개수 단위입니다. FPS 또는 `observation_strides`를 바꾸면 실제 시간 폭도 달라집니다. 순수한 밀도 효과를 비교할 때는 시간 폭을 맞춘 설정을 따로 사용하고, 고정 개수 설정과 구분해 보고합니다.

현재 파일럿 A는 Qwen 없이 CLIP만 사용합니다. Qwen 교체는 캡션·QA 단계에 영향을 주며 D0/D1/D2 경계 알고리즘 자체를 바꾸지는 않습니다.

## 입력 형식과 추가 구현 범위

- MP4를 직접 입력할 수 있습니다. `pilot: "a"`에서는 질문을 생략할 수 있습니다.
- 이미 추출된 프레임을 쓰려면 RGB 배열과 검증된 timestamp를 NPZ로 준비할 수 있습니다. 추출 FPS와 원본 frame index의 대응을 유지해야 합니다.
- NPZ에는 이미지가 들어갑니다. 제공된 사전 추출 특징 벡터만으로 현재 파이프라인을 실행할 수는 없습니다.
- 현재 `evidence_intervals`는 **QA 근거 구간**입니다. 이벤트 경계 정답을 이 필드에 넣지 않습니다.
- 경계 정답용 schema/변환기와 공식 평가 규칙을 반영한 evaluator를 추가해야 자동 정량 평가까지 연결됩니다. 현재는 경계 timestamp 및 HTML 진단을 내보내는 단계까지 구현되어 있습니다.
