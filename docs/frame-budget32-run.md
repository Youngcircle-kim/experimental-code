# 긴 영상의 16→32 프레임 예산 실험

이번 실험은 **QA 입력 320×320을 유지하고 프레임 수를 16장에서 32장으로
늘리는 예산 민감도 평가**다. 같은 긴 dev 영상 **20개·60문항**에서 여덟
선택 방법을 모두 32장으로 비교한다. 기존 cap128 D2/D0 구간과 CLIP 점수,
QA 모델·프롬프트·채점·선택지 순서 6개는 유지한다.

**주 비교는 D32−Uniform32**다. 구간화의 기여를 확인하는 핵심 보조 비교는
D32−C32이며, D_topk32−D32로 내부 선택의 영향을 확인한다. 기존 16장
결과와도 짝지어 각 방법의 32−16 변화와 D의 상대적 이득이 예산에 따라
달라지는지 계산한다.

## 이 실험을 하는 이유

이전 16장 실험에서 D와 D_topk의 정확도는 각각 44.17%, 43.89%였다.
D_topk−D는 −0.28%p, 영상 단위 95% 신뢰구간은 −5.56~+5.28%p여서,
내부 Top-k가 현재 D보다 낫다는 근거를 확보하지 못했다. 이 결과만으로 두
방법이 동등하다거나 더 많은 프레임에서도 같다고 결론 내릴 수는 없다.

32장에서는 입력 정보량이 늘었을 때 D의 Uniform 대비 이득이 유지되는지,
모든 방법이 비슷하게 좋아지는지, 선택 구조에 따라 변화량이 다른지 확인한다.
단순히 D32가 D16보다 높은지만 보면 더 많은 입력을 준 효과와 선택 방식의
이득을 구분하기 어렵다. 따라서 **동일 예산의 방법 간 비교**와 **동일
방법의 예산 간 비교**를 함께 수행한다.

이번 주 비교에는 기존 D를 유지한다. 앞선 결과에서 내부 Top-k가 명확히
우세하지 않았으므로, 후속 실험의 질문은 Top-k가 반드시 개선한다는 가정이
아니라 선택 방법의 효과가 더 큰 입력 예산에서도 남는지다. C도 32장으로
추가해, 내부 균등 선택을 유지한 상태의 D2 대 D0 비교를 직접 확보한다.

## 여덟 조건과 32장 선택 규칙

| 결과 이름 | 구간화 | 장수 배분 | 구간 내부 선택 |
|---|---|---|---|
| `uniform` | 전체 후보 | 해당 없음 | 전체에서 균등 32장 |
| `frame_top` | 전체 후보 | 해당 없음 | 질문–프레임 CLIP 상위 32장 |
| `temporal_bin` | 후보 수가 비슷한 시간순 32구간 | 구간마다 1장 | 각 구간의 최고 CLIP 점수 1장 |
| `D` | 저장된 cap128 D2 내용 변화 구간 | 저장된 구간 관련성으로 총 32장 재배분 | 균등 |
| `D_topk` | D와 같은 D2 | D의 32장 배분과 같음 | 질문–프레임 CLIP Top-k |
| `B_topk` | D와 같은 D2 | 구간 후보 수에 비례해 총 32장 배분 | 질문–프레임 CLIP Top-k |
| `C_topk` | 저장된 D0, D와 실제 구간 수 같음 | 저장된 C의 구간 관련성으로 총 32장 재배분 | 질문–프레임 CLIP Top-k |
| `C` | C_topk와 같은 D0 | C_topk의 32장 배분과 같음 | 균등 |

구간 수 상한 **128**과 프레임 예산 **32**는 다른 값이다. D0는 각 영상의
D2와 같은 실제 구간 수 K를 갖도록 후보 인덱스를 균등하게 나눈 구간이며,
Temporal-bin의 32개 구간과 다르다. D2는 특징 변화 구간이며 사람의 의미적
사건 경계를 보장하지 않는다.

32장 배분은 저장된 점수와 기존 온도·용량 제한·정수 배분 규칙으로 다시
계산한다. 16장 때 배분한 정수를 단순히 두 배로 만들지 않는다. 기존 선택
16장을 그대로 두고 16장을 덧붙이는 실험도 아니며, 각 방법이 새 예산에 맞게
선택을 다시 한다.

Top-k의 k는 해당 구간에 배정된 장수다. 최소 시간 간격은 0이며, 동점은
더 이른 후보를 우선한다. 최종 입력은 서로 다른 **32장**을 시간순으로
정렬한다. B_topk도 내부 선택에는 질문을 사용하므로 질문을 완전히 제거한
조건으로 해석하지 않는다.

## 32장은 이 데이터에서 무엇을 늘리는가

저장된 점수로 사전 계산한 D/C의 32장 배분은 현재 60문항 모두에서
**32개 구간에 한 장씩** 배분한다. 구간 안에서 두 장 이상을 관찰하는 형태가
아니다. 따라서 현재 설정에서는 주로 **관찰하는 구간의 수를 늘리는 실험**이다.

이 진단은 QA 정확도를 보지 않고 선택 계획에서 알 수 있다. D_topk−D와
C_topk−C는 같은 구간에서 대표 한 장을 균등 위치에서 고를지, 질문 관련성이
가장 높은 위치에서 고를지의 비교다. 구간 내부 동작을 여러 연속 프레임으로
더 자세히 관찰하는 효과를 검증했다고 표현하지 않는다.

구간 내부 관측 밀도가 별도 연구 질문이라면, 한 구간에 여러 장이 실제로
배정되는 설정을 따로 정의해야 한다. 구간 수·온도·집중 배분을 바꾸는 것은
현재 16→32 비교와 다른 개입이므로 이번 결과와 합쳐 설명하지 않는다.

## 가설과 비교의 역할

| 가설 | 비교 | 확인할 질문 |
|---|---|---|
| **주 가설: 동일 예산의 실용적 이득** | **D32−Uniform32** | 32장에서도 D가 균등 추출보다 정확한가 |
| 구간화 정책의 기여 | D32−C32 | 내부 균등 선택과 관련성 배분 규칙 아래 D2가 D0보다 유리한가 |
| 내부 선택의 기여 | D_topk32−D32 | 같은 D2·32장 배분 아래 Top-k가 더 좋은 대표 프레임을 고르는가 |
| Top-k를 유지한 구간화 기여 | D_topk32−C_topk32 | 내부 Top-k 아래 D2의 이득이 있는가 |
| Top-k를 유지한 배분 기여 | D_topk32−B_topk32 | D2 안에서 질문 관련성 장수 배분이 추가로 도움이 되는가 |
| 단순 선택 규칙 대비 이득 | D32·D_topk32와 Global Top-k32·Temporal-bin32 | 복잡한 구간화·배분의 이득이 간단한 대조군에도 남는가 |
| 예산 증가의 효과 | 각 방법의 32−16 | 어떤 방법에서 추가 16장이 도움이 되는가 |
| 예산에 따른 상대 이득의 변화 | (D32−Uniform32)−(D16−Uniform16) | D의 Uniform 대비 이득이 32장에서 더 커지는가 |

D32−C32에서 고정하는 것은 **구간 수와 관련성 배분 규칙**이다. 경계가
달라지면 구간 길이, 평균 특징, 관련성 점수와 실제 배분이 함께 달라진다.
따라서 이를 경계 위치 정확도만의 효과라고 부르지 않는다.

C·C_topk·D·D_topk는 질문 관련성 배분 아래 구간화와 내부 선택을 비교할
수 있는 조건을 제공한다. 그러나 후보 수 비례 배분의 모든 대응 조건까지
갖춘 전체 요인 실험은 아니다. 이번에 사전 지정한 직접 비교와 예산 간
상호작용을 중심으로 보고하며, 빠진 조건의 효과를 추정해 채우지 않는다.

## 16장 자료를 재사용하는 범위

`outputs/event_selection320_long`의 완료된 일곱 조건을 16장 기준값으로
사용한다. C16은 연결된 `outputs/resolution320_cap128_long`의 검증된
320 QA 결과에서 가져온다. 모두 같은 영상·문항·모델·프롬프트·채점 및
선택지 순서인지 확인한다.

**기존 16장 QA는 32장 QA 결과로 재사용하지 않는다.** 16장 자료는
32−16 변화와 예산에 따른 상대 이득을 계산하는 기준점이다. 32장 실험의
입력 선택 계획을 고정한 뒤 여덟 조건 모두 새 QA가 필요하다. 같은 문항에서
32장 인덱스·픽셀·모델·프롬프트·순서가 완전히 같은 조건끼리만 공유한다.

후보·구간·CLIP 점수는 기존 자료를 재사용한다. **선택용 후보/CLIP의
224×224 설정**과 **QA의 320×320 설정**을 구분한다. 새 CLIP 추출이나
구간 재검출 없이 저장된 특징 유래 점수와 경계를 사용하고, QA용 선택 픽셀은
원본에서 320으로 검증한다. 선택지·정답·근거 주석·새 캡션을 선택에 넣지
않는다.

새 QA의 공유 전 상한은 **60문항 × 8조건 × 6순서 = 2,880회**다.
한 번의 QA는 한 선택지 순서에서 모든 선택지를 채점하는 단위이며 모델
forward 한 번과 같지 않다. 16장 조건의 재실행은 이 상한에 포함하지 않는다.
아래 메모리 점검의 실제 QA 한 번은 이 2,880회 안에 포함되며, 같은 실행
폴더의 전체 평가에서 재사용한다.

## 통계와 판정

문항마다 6개 선택지 순서의 정답 여부를 먼저 평균한다. 전체 정확도는 문항에
동일한 가중치를 주고, 같은 영상에 속한 문항과 모든 조건의 짝을 유지하는
**영상 단위 paired bootstrap 5,000회**로 95% 신뢰구간을 계산한다.
선택지 순서 반복을 독립 문항으로 세지 않는다.

예산 상호작용은 문항별로 다음 값을 먼저 계산한다.

```text
q별 예산 상호작용 = (D32_q − Uniform32_q) − (D16_q − Uniform16_q)
```

이 문항별 네 항을 같은 영상과 함께 재표집해 신뢰구간을 구한다. 두 개의
독립된 신뢰구간 끝점을 빼서 상호작용의 구간으로 사용하지 않는다.

양수이면 D의 상대 이득이 32장에서 커지고, 음수이면 줄어든다. 0을 포함하면
이 표본에서 상대 이득의 변화를 확정하기 어렵다. D32−D16이 양수라는 것만으로
상호작용도 양수라고 결론 내리지 않는다. Uniform이 더 크게 좋아질 수도 있다.

각 비교에서 개선·하락·동일 문항 수는 문항별 6순서 평균을 비교해 센다.
평균 차이, 신뢰구간, 문항 변화를 함께 보고한다. 주 비교의 신뢰구간 하한이
0보다 크면 이 dev에서 D32의 Uniform32 대비 개선을 뒷받침하지만, 반복
탐색에 따른 일반화 한계는 남는다. 보조 비교는 다중비교 보정 전 개별 구간이며
유리한 비교를 사후에 주 가설로 바꾸지 않는다.

## 비용과 실행 가능성

보고 비용은 **QA 비용**이다. 재사용한 CLIP 특징 추출·구간화·프레임 선택
비용을 포함하지 않는다. 같은 320 processor 조건에서 16장의 시각 토큰은
1,600개이고, 32장은 **QA 한 순서당 3,200개**를 기대하며 실제 processor
기록으로 확인한다. 문항마다 여섯 순서가 반복되므로 3,200을 여섯 순서 전체의
합계로 읽지 않는다.

프레임 수가 두 배여도 실행 시간이나 최대 GPU 메모리가 정확히 두 배라는
보장은 없다. 실제 한 문항의 processor·메모리 점검과 QA 측정값으로 확인한다.
해상도·정밀도·모델·채점 방식을 자동으로 낮춰 32장 실행을 맞추면 기존
16장과의 비교 조건이 달라진다. 메모리 부족은 별도로 기록하고, 조건을 바꾼
실행은 별도 프로토콜로 취급한다.

과거 16장 QA 시간과 새 32장 QA 시간을 구분한다. 새로운 32장 실행 내부의
동일 입력 공유는 한 번만 비용으로 집계한다. 이 결과만으로 전처리를 포함한
전체 처리 효율이나 비용 대비 최고 성능을 주장하지 않는다.

### 실제 메모리 점검 기록 — 2026-10-02

`outputs/frame_budget32_long/memory_check.json`에 실제 점검 결과를 저장했다.
882-3 문항의 Uniform32·첫 선택지 순서 QA 1회가 오류 없이 완료됐다.
processor에서 320×320 이미지 32개와 시각 토큰 3,200개를 확인했다.
QA 시간은 **26.02초**, 모델을 포함한 PyTorch 최대 할당 메모리는
**11.72GiB**였다. RTX 3060 12GB에서 여유가 작은 상태이므로, 한 입력의
성공을 전체 실행의 메모리 보장으로 해석하지 않는다.

최대 reserved 값은 약 18.09GiB다. 이는 PyTorch allocator 지표이며
GPU의 물리 VRAM 용량이나 전용 VRAM 실제 점유량과 같지 않다.
실행 중 별도 `nvidia-smi` 표본에서는 메모리 사용량 12,068MiB,
여유 48MiB를 관찰했으나, 연속 측정한 최대값은 아니다.

26.02초를 2,880회에 단순 적용하면 **QA만 약 20.8시간**이다. 첫 호출과
문자 수가 가장 긴 문항 한 개의 측정이므로 전체 실행 시간 예측값으로
확정하지 않는다. 디코딩·모델 로딩 시간은 이 환산과 QA 비용에서 제외한다.
현재는 준비와 이 1회 점검까지 완료했으며 전체 evaluate는 실행하지 않았다.
고유 QA 계획은 2,880회이고, 저장된 점검 trial을 재사용하면 **2,879회**가
남는다. 전체 테스트 262개(새 실험 테스트 38개 포함)와 신규 파일 Ruff
검사가 통과했다.

`memory-check`는 선택된 대상 중 질문과 선택지의 **문자 수 합이 가장 긴
문항**에서 Uniform32와 첫 번째 선택지 순서를 사용한다. 길이 기준 선택이며
정답률로 문항을 고르지 않는다. 문자 수가 GPU 사용량의 최댓값을 보장하지는
않으므로, 한 번의 성공만으로 모든 입력이 들어간다고 결론 내리지 않는다.

이 단계는 실제 QA이며 `memory_check.json`에 판정·시각 토큰·processor·
최대 GPU 메모리·시간을 기록한다. 검증된 trial은 `trials/`에 저장해
전체 evaluate에서 재사용한다. 같은 명령을 다시 실행해 유효한 trial이 이미
있으면 QA를 반복하지 않는다. 준비 상태와 메모리 점검 결과를 구분하며,
`passed_one_QA_call` 기록이 없는데 점검이 통과했다고 표현하지 않는다.

전체 32장 QA 평가:

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_budget_dev --phase evaluate --output-dir outputs/frame_budget32_long
```

중단되면 같은 evaluate 명령을 다시 실행한다. 완료된 체크포인트를 검증해
재사용하며, 소스·코드·설정·대상 범위가 달라지면 같은 폴더에서 이어서
실행하지 않는다. 같은 출력 폴더에 두 프로세스를 동시에 실행하지 않는다.

한 영상·한 문항 smoke는 전체 실험과 다른 폴더를 사용한다.

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_budget_dev --phase prepare --max-videos 1 --max-questions 1 --output-dir outputs/frame_budget32_smoke
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_budget_dev --phase evaluate --max-videos 1 --max-questions 1 --output-dir outputs/frame_budget32_smoke
```

한 문항 smoke도 여덟 조건·여섯 순서이므로 공유 전 상한은 **48회 QA**다.
단일 조건·단일 순서 메모리 probe와는 다른 실행이다. 한 영상의 smoke에는
영상 간 변동을 추정할 표본이 없으므로 전체 결과처럼 신뢰구간을 해석하지
않는다.

전체 완료 후 재집계:

```powershell
.\.venv\Scripts\python.exe -B -m event_caption_pilot.frame_budget_dev --phase summarize --output-dir outputs/frame_budget32_long
```

최종 전달 파일:


완료 전 선택 계획이나 메모리 probe를 최종 정확도 결과로 대신하지 않는다.
고정 프로토콜, 문항별 원시 결과·선택 프레임, 재개용 체크포인트도 보존한다.

기본 `--source-dir`은 `outputs/event_selection320_long`이다. 같은
출력 폴더에서 prepare·memory-check·evaluate·summarize를 이어서 사용할

## 저장 파일과 결과 키

| 파일 | 내용 |
|---|---|
| `prepare_complete.json` | 준비 상태, 대상 수, 신규 QA 상한·고유 입력 계획 수, 신규 CLIP 0회, D의 구간당 한 장 배분 문항 수 |
| `protocol.json`, `selection_plans.json` | 소스·설정·코드 해시, 32장 경계·배분·선택 계획 |
| `memory_check.json` | 실제 QA 한 번의 메모리 점검 결과와 재사용 trial 키 |
| `trials/`, `questions/` | 선택지 순서별 QA 및 완료 문항 체크포인트 |
| `decode/`, `backend.json` | 전체 평가의 디코딩 검증과 QA 런타임 정보 |
| `progress.json` | 완료 문항 수와 현재 호출에서 추가한 QA 수 |
| `results.json` | 모든 문항의 여덟 조건 원시 결과와 요약 |
| `question_metrics.csv`, `selected_frames.csv` | 문항별 평균·차이 및 조건별 선택 인덱스·시각 |
| `handoff.json` | 전체 완료 후 최종 요약 |

`handoff.json`의 `frame_budget`은 32, `baseline_frame_budget`은 16이다.
`overall.metrics`의 `D`, `uniform` 등은 **32장 정확도**이며,
16장 기준 정확도는 `baseline_overall.metrics`에 있다. 같은 예산의 비교는
`D_minus_uniform`, `D_minus_C`, `D_topk_minus_D` 등이다.

예산 변화 키는 `D_32_minus_16`, `uniform_32_minus_16`처럼 각 조건명에
`_32_minus_16`을 붙인다. 네 항의 예산 상호작용 키는
`D_uniform_advantage_change`다. 정확도·차이의 평균과 신뢰구간은 모두
비율 단위이므로, 퍼센트 또는 %p로 표시할 때 100을 곱한다.
`paired_question_changes`는 각 비교의 개선·하락·동일 문항 수다.

`resources`는 32장 조건별 QA 시간 중앙값·최대 GPU 메모리·시각 토큰을
제공한다. `visual_tokens_per_QA_call=3200`,
`option_order_repeats_per_question=6`으로 단위를 구분한다.
`unique_new_QA_calls`와 `unique_new_QA_seconds`는 공유된 실행을 한 번만
센 이번 32장 실험 전체의 누적 QA 수·시간이다. 성공한 memory-check trial도
전체 완료 결과에 포함된다. 과거 16장 QA 비용은 이 합계에 넣지 않는다.
`progress.json`의 `new_QA_calls_this_invocation`은 현재 명령 호출에서
새로 수행한 수이므로 누적 수와 다를 수 있다.

## 논문에 어느 수준의 근거가 되는가

32장은 관련 논문에서 사용된 예산 중 하나다. 예를 들어 AKS는 Qwen2-VL과
LLaVA-OV에 32장, LLaVA-Video에 64장을 사용하며 두 벤치마크와 세 모델에서
평가했다. 프레임 수 32 자체가 모든 논문의 공통 표준이라는 근거는 아니다.
[AKS 원문 실험 설정과 Table 1](https://arxiv.org/html/2502.21271v1#S4.SS1)

Video-MME 공식 데이터는 900영상·2,700문항이며, 공식 표에는 모델별로
16·32·64·128장 등 다양한 입력 예산과 자막 조건이 함께 제시된다. 이번
20영상·60문항의 긴 영상 표본 점수를 그 전체 벤치마크 순위와 직접 비교할 수
없다. 모델·해상도·후보 FPS·선택 점수·채점 규칙도 맞아야 선택기의 차이를
공정하게 비교할 수 있다. [Video-MME 공식 소개 및 결과표](https://video-mme.github.io/home_page.html)

| 주장 수준 | 이번 실험으로 평가할 수 있는 범위 | 추가로 필요한 근거 |
|---|---|---|
| 구현·실행 가능성 | 현재 장비와 모델에서 32장을 동일 조건으로 처리하는지 | 실제 processor·메모리·입력 검증 |
| 제한된 표본의 효용 | 같은 dev·같은 모델에서 D32가 Uniform32보다 좋은지 | 새 독립 표본에서 재확인 |
| 예산에 대한 견고함 | 16→32에서 성능과 D의 상대 이득이 어떻게 변하는지 | 더 넓은 예산 범위의 정확도·비용 곡선 |
| 구성요소의 기여 | 특정 구간화·배분·내부 선택 조건 아래의 직접 차이 | 주장할 상호작용에 필요한 대응 조건 |
| 일반적 선택 알고리즘의 우수성 | 이번 실험만으로 확정할 수 없음 | 다른 QA 모델·다른 데이터셋·전체 평가·동일 조건 선행방법 비교 |
| 전체 효율 | QA 비용의 제한된 비교 | 최초 특징 추출과 질문 간 공유를 포함한 전체 비용 |

따라서 이번 실험은 논문의 **예산 민감도 분석과 구성요소 분석에 들어갈
탐색적 근거**를 만들 수 있다. 하지만 동일 dev에서 반복 설계를 했고 기존
holdout 결과도 이미 관측했으므로, 긍정적 결과가 나와도 그것만으로 새 독립
확증이나 일반적인 우월성이 성립하지 않는다. 변경안을 고정한 뒤 설계에
사용하지 않은 영상 표본, 다른 모델 또는 데이터셋에서 확인해야 한다.

관련성·시간 분산을 함께 고려하는 프레임 선택 자체는 AKS에서도 다루는
문제다. 현재 방법은 저장된 D2 내용 변화 구간과 구간별 장수 배분이라는
구현을 평가한다. 그 차이가 학술적으로 새로운 기여인지는 문헌 비교와
동일 조건의 직접 실험으로 별도 입증해야 한다.
[Adaptive Keyframe Sampling 논문](https://arxiv.org/abs/2502.21271)
