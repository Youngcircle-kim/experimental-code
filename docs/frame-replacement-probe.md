# 근거 프레임 한 장 교체 진단

문항 `856-1`에서 원래 D가 고른 1152번을 사람이 찾은 1035번으로 교체한다.
나머지 15장, 시간순, 구간별 배정 장수, 모델, QA 프롬프트, 로그우도 채점,
선택지 순서 6개를 유지한다. 정답이나 근거 메모를 모델 프롬프트에 넣지 않는다.

기본 조건은 다음과 같다.

| 조건 | 프레임 | QA 호출 |
|---|---|---:|
| `saved_D` | 저장된 원 D | 0, 과거 결과 참조 |
| `rerun_D` | 원 D의 동일한 16장 | 6 |
| `replace_1152_with_1035` | 1152 대신 1035, 나머지 15장 동일 | 6 |

`rerun_D`를 주 대조 조건으로 쓰고 과거 `saved_D`와의 재현성도 따로 기록한다.
선택한 한 장의 실제 시각도 함께 바뀐다. 프레임 예산은 같지만 타임스탬프 문자열에
따라 입력 토큰 수는 달라질 수 있으므로 토큰 예산 고정 실험으로 표현하지 않는다.

## 실행

저장소 루트 `C:\Users\dudgh\experimental-code`에서 먼저 입력만 확인한다.
이 단계에는 영상 디코딩이나 GPU 추론이 없다.

```powershell
.\.venv\Scripts\python.exe -B -m event_caption_pilot.frame_replacement_probe --check-inputs
```

새 실행에는 기본적으로 12회 QA가 필요하다. 각 QA는 선택지별 채점을 포함한다.
영상 디코딩과 모델 로딩도 수행한다.

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_replacement_probe
```

기본 출력은 `outputs/frame_replace_856_1_1035`이다. 이미 실행된 폴더가 있으면
덮어쓰지 않는다. 중단 후 재개 또는 완료 결과 재집계:

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_replacement_probe --resume
```

완료된 순서는 원자적 체크포인트에서 재사용한다. 완료 후 재개는 QA를 다시 하지
않지만 후보 픽셀을 확인하기 위해 영상 디코딩은 반복한다. 코드·설정·원본·교체
프레임 목록이 바뀌면 재개를 거부하므로 별도 출력 폴더를 지정해야 한다.
같은 출력 폴더로 두 프로세스를 동시에 실행하지 않는다.

1036도 별도의 처치 조건으로 확인하려면:

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_replacement_probe --replacements 1035 1036 --output-dir outputs/frame_replace_856_1_two_candidates
```

이는 1035/1036을 동시에 추가하는 방식이 아니다. **각각 별도의 16장 입력**으로
시험하며, 대조 6회 + 두 처치 각 6회로 총 18회 QA를 수행한다.

다른 문항은 `--video-id`, `--question-id`, `--remove-index`, `--replacements`를
명시한다. 교체 대상은 D가 한 장만 배정한 구간의 중앙 프레임이어야 하고,
대체 프레임은 같은 구간 안의 미선택 후보여야 한다.
`--input-dir`는 factorial 실행 디렉터리다. 원 frozen baseline이 기본 위치
(`input-dir`의 형제 디렉터리 `videomme_dev_frozen`)에 없으면 `--baseline-dir`로 지정한다.

## 출력 읽기

- `summary.md`: 세 조건의 순서 평균 정확도와 원 D 재현 여부.
- `results.json`: 전체 입력 인덱스·시각·순서별 점수·예측·요약.
- `paired_orders.csv`: 순서별 원 선택지 인덱스, 정답 여부, 정답 선택지 margin.
- `protocol.json`: 변경 내용, 고정 설정, 원본·코드 해시.
- `trials/*.json`: 순서별 재개용 결과.
- `progress.json`, `backend.json`: 진행 상황과 실제 모델/실행 환경.

CSV의 `original_answer_index`는 **0부터 시작하는 원래 선택지 번호**이다.
이 문항의 정답 인덱스 3은 화면의 4번 선택지이다.
`gold_margin`은 정답 선택지 점수에서 가장 높은 오답 선택지 점수를 뺀 값이다.
원 QA 설정은 토큰 평균 로그우도이므로 margin은 확률 차이가 아니다.

먼저 `baseline_reproduction.same_original_predictions`를 확인한다.
`max_abs_option_score_difference`도 함께 기록하므로 예측만 같은 경우와 점수까지
같은 경우를 구분할 수 있다. 재실행 D가 과거와 다르면 과거 D 대비 결과를
순수한 프레임 효과로 해석하지 말고, 현재 `rerun_D`와 처치의 대응 비교를 본다.

교체 후 정답이 늘면 **이 문항에서 사람이 지정한 근거 프레임 교체가 동일 QA의
답변을 개선했다**고 기록한다. 정답이 늘지 않으면 곧바로 QA만의 문제라고
단정할 수 없다. 추가 시간 맥락, 여러 근거 장면, 해상도, 인식·추론·채점 문제가
남을 수 있다.

선택지 순서 6개는 한 문항의 반복이다. 독립 표본 6개처럼 신뢰구간이나 유의성을
계산하지 않는다. 사람이 정답 근거를 보고 고른 사후 진단이며 자동 선택 방법의
일반 성능이나 전체 데이터셋의 개선 효과를 나타내지 않는다.

## 원본과 비교 조건 검증

원 factorial 프로토콜·계획·문항 결과·backend 해시, 원 frozen baseline과 manifest,
QA/디코딩/seed 코드 해시, 모델 리비전·라이브러리 버전 등 실제 metadata,
디코딩한 후보 픽셀과 시각, 기존 D 입력 시각을 확인한다.
순서별 정답 라벨·선택지 매핑과 예측이 점수의 argmax인지도 검사한다.
원 실험 결과나 검토 페이지의 수동 판정은 수정하지 않는다.

## 이번 실제 실행 결과

`outputs/frame_replace_856_1_1035`에 실행을 완료했다.

| 조건 | 맞힌 선택지 순서 수 |
|---|---:|
| 저장된 D | 0/6 |
| 동일 입력으로 재실행한 D | 0/6 |
| 1152 → 1035 교체 | 0/6 |

재실행 D는 과거와 모든 예측 및 선택지 점수가 일치했다(최대 점수 차이 0).
교체 후에도 모든 순서에서 원래 3번 선택지인 “아기가 행복했고 엄마가 먹였다”를
선택했다. 정답은 4번 “아기가 불편해했다”이다.

이 결과는 현재 16장 입력과 로그우도 QA에서 1035번 한 장으로의 교체만으로
오답을 수정하지 못했다는 뜻이다. 내부 선택 실패가 없었다는 뜻은 아니며,
QA 인식·시간 맥락·다른 프레임의 영향·채점 중 어느 것이 추가 병목인지는
이 비교만으로 구분되지 않는다. 이 실행에서 1036번 별도 처치는 하지 않았다.

## 1035와 1036을 동시에 넣는 별도 진단

두 장을 함께 넣는 실행기는 `frame_pair_probe.py`이다. 앞의
`--replacements 1035 1036`은 각 한 장을 따로 시험하므로 구분해야 한다.

```powershell
.\.venv\Scripts\python.exe -B -m event_caption_pilot.frame_pair_probe --check-inputs
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_pair_probe
```

1152를 제거하고 1035와 1036을 모두 넣는다. 나머지 15장은 유지하므로
**기존 D 16장과 처치 17장의 비교**이다. 구간 수와 다른 구간의 선택은 유지되지만,
구간 10의 배정은 1장에서 2장으로 바뀐다. 프레임·토큰 예산 고정 비교가 아니다.
두 근거 프레임은 0.5초 간격이므로 긴 시간 맥락을 추가한 실험으로 표현하지 않는다.

원 D 재실행 6회와 두 장 동시 입력 6회로 총 12회 QA를 수행한다.
출력은 `outputs/frame_pair_856_1_1035_1036`이며 완료 후에는 `--resume`으로
기존 결과를 재집계할 수 있다. 새 실행은 다른 `--output-dir`을 지정한다.
이전 한 장 교체 코드와 결과는 변경하지 않는다.

실제 동시 입력 결과도 **0/6**이었다. 17장 입력에서도 모든 순서에서 원래
3번 선택지를 예측했다. 원 D 재실행은 기존 예측과 선택지 점수를 정확히
재현했다(최대 절대 차이 0). 따라서 이 문항의 현재 로그우도 QA에서는
1035·1036을 함께 보충해도 정답으로 바뀌지 않았다. 두 프레임만 단독으로
보여주는 실험은 아직 수행하지 않았으며, 다른 15장의 영향과 인식·채점 문제는
이번 비교만으로 분리되지 않는다.

## 1035·1036 두 장만 단독으로 입력

`--only-pair`를 사용하면 기존 D 프레임을 모두 제외하고 근거 두 장만 입력한다.
원래 D 16장 재실행과 단독 2장 입력을 같은 QA·선택지 순서로 비교한다.

```powershell
.\.venv\Scripts\python.exe -B -u -m event_caption_pilot.frame_pair_probe --only-pair
```

출력은 `outputs/frame_pair_only_856_1_1035_1036`이다. 이전 한 장 교체와
17장 결과는 그대로 보존한다. 입력 장수와 시각적 맥락이 함께 줄어드는 진단이며,
개별 방해 프레임이나 내부 attention 동작을 특정하는 실험은 아니다.
재실행 시 코드/프로토콜이 달라졌으면 `--resume` 대신 새 `--output-dir`을 사용한다.

두 장 단독 실제 결과도 0/6으로, 모든 순서에서 원래 3번 선택지를 예측했다.
다만 정답 4번과 최상위 오답 간 평균 로그우도 margin은 원 D 약 -0.3702에서
두 장 단독 약 -0.1596으로 개선됐고, 여섯 순서 모두 격차가 줄었다.
선택지 순위를 뒤집지는 못했지만 입력 변화에 점수가 반응한 것이다.
다른 프레임 제거만으로 오답이 해결되지 않았으므로 장면 해석·질문 맥락·
선택지 채점의 추가 진단이 필요하다. 실행 시점 소스는 해당 출력 폴더의
`runner_source.py`에 보존했다.
