# 긴 영상 QA·프레임 선택 연구의 입력 사양 비교

확인일: 2026-09-28. Exa 검색 3개 갈래, 검색 결과 22건(중복 포함), 주요 논문 원문 6편 확인. 아래는 2024–2025년의 관련 대표 사례이며, 분야 전체의 통계나 최신 모델 순위는 아니다.

현재 실험의 224×224는 아래 고정 해상도 사례보다 작다. 그러나 최종 8·16장만 사용하는 프레임 선택 연구도 있으므로, 16장이라는 이유만으로 기존 실험의 입력이 부적절하다고 판단할 수는 없다. 후보 프레임 수, 최종 QA 프레임 수, 실제 시각 토큰 수를 구분해야 한다.

## 해상도와 토큰 예산

LLaVA-OneVision의 384×384 프레임은 인코더에서 729개 토큰을 만든 뒤 비디오 경로에서 196개로 줄인다. 따라서 동일한 해상도라도 모델의 패치 크기, 공간 병합, 시간 압축에 따라 LLM에 들어가는 시각 토큰 수가 다르다. 다른 모델의 토큰 수 비율을 시간·VRAM 비율로 해석할 수 없다. [원문 Appendix C.1](https://arxiv.org/html/2408.03326v2)

현재 프로젝트는 비디오 프레임을 독립된 이미지 목록으로 Qwen에 전달한다. 로컬 모델 설정의 patch_size=16, spatial_merge_size=2를 적용하면, 정사각형 이미지 한 장의 병합 후 시각 토큰 수는 (한 변 / 32)^2이다. 아래 값은 텍스트와 이미지 경계 토큰을 제외한 계산값이며, 실행 시간이나 VRAM 실측값은 아니다.

| QA 입력 | 시각 토큰 수 | 현재 대비 |
|---|---:|---:|
| 16장 × 224×224 | 784 | 1.00배 |
| 32장 × 224×224 | 1,568 | 2.00배 |
| 16장 × 320×320 | 1,600 | 2.04배 |
| 16장 × 448×448 | 3,136 | 4.00배 |

32장×224와 16장×320은 LLM 시각 토큰 수가 비슷해 공간 정보와 시간 정보의 배분을 비교하는 데 유용하다. 다만 이미지 개수에 따른 경계 토큰과 비전 인코더 비용 등은 달라 엄밀히 동일한 계산량은 아니다.

Q-Frame Table 6에서는 고해상도 8장의 평균 Tokens/Video가 2,265.1이고, 고·중·저해상도 4·8·32장 조합은 2,344.8이다. 논문은 전처리 때문에 토큰 수가 약 3.5% 늘어났음을 함께 보고한다. 즉, 44장이라는 프레임 수만으로 고해상도 44장 입력과 같은 비용이라고 볼 수 없다. [Q-Frame Table 6](https://arxiv.org/html/2506.22139v3)

## GPU 보고값의 해석

Frame-Voyager는 모듈 학습에 VILA-8B 기준 H100 8장, VILA-40B 기준 H100 32장을 사용했다고 보고한다. 추론 실험에는 H100 8장을 사용했다고 명시한다. Q-Frame도 실험 환경으로 H100 8장을 보고한다. 이는 저자들이 사용한 실험 환경이며, 한 질문을 batch size 1로 처리하기 위한 최소 GPU 요구량이나 모델 하나가 반드시 GPU 8장을 점유한다는 증거는 아니다. [Frame-Voyager §4.1](https://arxiv.org/html/2410.03226), [Q-Frame §4.1](https://arxiv.org/html/2506.22139v3)

따라서 이 보고값으로 현재 RTX 3060 12GB에서 24/32장 또는 448×448 입력이 가능하다고 보장하거나 불가능하다고 단정할 수 없다. 실제 peak VRAM과 질문당 실행 시간을 측정해야 한다.

## 현재 연구에 대한 제안

1. 우선 선택된 프레임의 인덱스를 고정하고, QA 입력만 224→320→448로 바꿔 공간 해상도 효과를 분리한다. 먼저 소수 질문으로 메모리와 처리 시간을 확인한다.
2. 원본 영상에서 더 높은 해상도로 다시 추출해야 한다. 이미 224×224로 저장된 이미지를 확대하거나 Qwen의 max_pixels만 올리는 것은 원본 세부 정보를 복원하지 않는다.
3. 현재 CLIP 후보 점수와 이벤트 분할은 그대로 재사용하고, QA용 이미지의 해상도만 바꾸면 선택기 변경과 읽기 능력의 변화를 구분하기 쉽다.
4. 프레임 수 실험은 같은 224 해상도에서 16→32로 별도 비교한다. 해상도와 프레임 수를 동시에 바꾸면 개선 원인을 구분하기 어렵다.
5. 1035·1036 사례에서 높은 해상도로 정답이 바뀌는지는 아직 확인하지 않았다. 해상도를 현재 오답의 원인으로 확정해서는 안 된다.
